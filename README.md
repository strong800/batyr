# Сайт группы компаний «Батырхан»

Локальный сайт компании: каталог проектов домов из профилированного бруса, галерея реализованных объектов, калькулятор, заявки и админ-панель. Всё работает на одном ноутбуке, без облачных сервисов и платных подписок.

**Стек:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · Framer Motion · SQLite через Prisma · sharp для изображений · ffmpeg для видео.

---

## Запуск в две команды

```bash
npm run setup
```

```bash
npm run dev
```

Сайт откроется на `http://localhost:3000`, админка — на `http://localhost:3000/admin`.

`npm run setup` делает всё разом: генерирует Prisma-клиент, создаёт базу, обрабатывает фотографии и видео из папки с материалами и наполняет базу контентом.

## Что нужно один раз перед первым запуском

### 1. Установить зависимости

```bash
npm install
```

npm 11 по умолчанию блокирует установочные скрипты пакетов. Если увидите предупреждение `allow-scripts`, разрешите их — без этого не соберутся `sharp`, `prisma` и `esbuild`:

```bash
npm approve-scripts prisma @prisma/client @prisma/engines sharp esbuild
```

После этого повторите `npm install`. В `package.json` разрешения уже прописаны, так что на этой машине шаг обычно не требуется.

### 2. Создать `.env.local`

Скопируйте `.env.example` в `.env.local` и заполните. Минимум — логин, пароль и секрет:

```bash
copy .env.example .env.local
```

Секрет для подписи куки сессии генерируется так:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

| Переменная | Зачем | Обязательна |
|---|---|---|
| `ADMIN_LOGIN` | Логин для входа в `/admin` | да |
| `ADMIN_PASSWORD` | Пароль | да |
| `AUTH_SECRET` | Подпись httpOnly-куки сессии | да |
| `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` | Ключ JS API Яндекс.Карт | нет |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | Номер счётчика Метрики | нет |
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта для sitemap и Open Graph | нет |

Без ключа Яндекс.Карт карта не ломается: на её месте появляется блок с адресом и кнопкой «Построить маршрут», а внешних запросов не уходит вовсе.

### 3. Загрузить шрифты

```bash
npm run fonts:fetch
```

Скачивает Oswald и Golos Text (кириллица и латиница, ~160 КБ) в `public/fonts`. Нужен интернет — но только один раз. Дальше проект собирается офлайн: при сборке в Google ничего не ходит.

### 4. Поставить ffmpeg — для видео

Видео обрабатывается локально. Проще всего:

```bash
pip install imageio-ffmpeg
```

Скрипт импорта сам найдёт бинарник. Также подойдёт `ffmpeg` в `PATH` или переменная `FFMPEG_PATH`. Если ffmpeg не найден, импорт не падает: фотографии обработаются, а видео и стоп-кадры цеха будут пропущены с предупреждением.

## 📹 Куда класть видеоотзывы

**Папка: `media/reviews/`** в корне проекта.

Положите туда файлы роликов и выполните:

```bash
npm run reviews:import
```

Отзывы появятся в блоке «Отзывы» на главной сразу после выполнения команды — пересобирать сайт не нужно.

### Почему отдельно от остальных медиа

Фотографии и ролик о производстве лежат в одной папке с материалами и обрабатываются командой `media:import`. Отзывы приходят иначе: поштучно, в разное время, от разных заказчиков. Поэтому у них своя папка и своя команда — чтобы добавить один новый отзыв, не нужно трогать остальные 40 фотографий.

### Что скрипт делает с файлами

| Шаг | Результат |
|---|---|
| Сжимает | Веб-версия `mp4`, ширина не больше 720 px. Ролик на 180 МБ становится 5–6 МБ |
| Снимает постер | Кадр со второй секунды: на первом часто смазано или темно |
| Сохраняет оригинал | `public/uploads/originals/reviews/` — веб-версия сжата с потерями |
| Заводит запись | Отзыв в базе с привязанным видео, сразу видимый на сайте |

### Что важно знать

**Имя файла становится адресом.** `Отзыв Марии.MOV` → `otzyv-marii.mp4`. Кириллица транслитерируется, пробелы заменяются дефисами — можно называть файлы по-русски.

**Имя файла — это ключ записи.** Повторный запуск команды дубликат не создаст: файл с тем же именем обновит существующий отзыв. А вот если файл переименовать, заведётся новый отзыв, а старый останется в базе — удалите его в админке.

**Имена заказчиков скрипт не выдумывает.** У нового отзыва подставляется нейтральное «Заказчик». Настоящее имя, город и текст впишите на `/admin/reviews`. Придумывать за заказчиков, что они сказали, я не стал — по тем же соображениям в базе сейчас стоят «Заказчик» и «Заказчица», а не выдуманные имена.

**Форматы:** `.mp4`, `.mov`, `.m4v`, `.avi`, `.mkv`, `.webm`. Вертикальная съёмка с телефона — нормально, плеер показывает ролики в родном формате и не грузит их, пока не нажали play.

**Если ролики лежат в другом месте** — путь переопределяется переменной `BATYR_REVIEWS_DIR`, копировать файлы в проект тогда не нужно.

**Пересжать уже обработанное:**

```bash
npm run reviews:import -- --force
```

### На новой машине

Сами ролики в git не попадают — в репозитории лежит только `media/reviews/README.md` с этой же инструкцией. После клонирования положите файлы в папку и выполните команду: пять отзывов, которые сейчас на сайте, восстанавливаются именно так.

## Как работает обработка медиа

Скрипт `media:import` читает исходную папку (по умолчанию `C:\Users\Almaz\Desktop\Батырхан`, переопределяется переменной `BATYR_MEDIA_DIR`) и:

1. Копирует **оригиналы без изменений** в `public/uploads/originals/`.
2. Конвертирует в webp и нарезает ширины 480 / 800 / 1280 / 2048.
3. Применяет поворот по EXIF — перевёрнутых фото не будет.
4. Считает крошечный blur-плейсхолдер для плавной подгрузки.
5. Готовит веб-версию видео, постер-кадр и восемь стоп-кадров производства.

Кадрирование и цветокоррекция не применяются — фотографии идут как есть.

**Про видеоотзывы.** Обрабатываются отдельной командой `reviews:import` из папки `media/reviews/` — см. раздел «Куда класть видеоотзывы». Пять роликов с телефона, 292 МБ исходников, приведены к ширине 720 px и сжаты до **46 МБ** суммарно. Играют в родном вертикальном формате, не грузятся до нажатия play.

**Про видео производства.** Исходник вертикальный (720×1280), 48,8 с, с озвучкой и вшитыми субтитрами. Веб-версия обрезана на 39,5 с: убран финальный призыв «напишите мне в директ слово ДОМ», который на сайте выглядел бы как перепост из соцсетей. Ролик стоит в родном вертикальном формате, играет без звука с кнопкой включения, а `preload="none"` означает, что его 6,8 МБ не загружаются, пока не нажат play, — на метрики производительности он не влияет.

## Скорость и доступность: измерено

Замерено Lighthouse 12 по **продакшн-сборке** (`npm run build` + `npm start`), а не по dev-серверу — на dev-е цифры не показательны.

### Десктоп

| Страница | Performance | Accessibility | Best Practices | SEO | LCP | CLS |
|---|---:|---:|---:|---:|---:|---:|
| Главная | 100 | 100 | 100 | 100 | 0,8 с | 0 |
| Каталог | 99 | 100 | 100 | 100 | 1,0 с | 0 |
| Карточка проекта | 99 | 100 | 100 | 100 | 0,8 с | 0 |
| Реализованные объекты | 99 | 100 | 100 | 100 | 1,0 с | 0 |
| Производство | 99 | 100 | 100 | 100 | 0,9 с | 0 |

Цель из ТЗ — Performance и Accessibility выше 90 на десктопе — выполнена с запасом: минимум по всем страницам 99 и 100.

### Мобильный

**Performance ≈ 82** (медиана четырёх прогонов, разброс 70–86), Accessibility, Best Practices и SEO — 100. Это ниже 90, и вот честная причина: Lighthouse в мобильном профиле замедляет процессор вчетверо и эмулирует медленный 4G. Основная задержка — не картинки (кадр первого экрана весит 41 КБ и грузится за 375 мс), а гидратация React в главном потоке.

Чтобы поднять мобильный выше 90, нужно убирать Framer Motion с первого экрана и переводить анимации появления на CSS. Это заметный рефакторинг, и на десктопные метрики он не влияет — поэтому я его не делал. Скажите, если нужно.

### Что было исправлено по итогам замеров

- **Постеры видео грузились дважды.** Атрибут `poster` у `<video>` браузер тянет немедленно и в полном размере, игнорируя `preload="none"`. На мобильном это отнимало почти 200 КБ у картинки первого экрана. Теперь постер — обычный `next/image` поверх плеера: ленивый и в нужном размере.
- **У LCP-картинки не было `fetchpriority`.** Одного `priority` у `next/image` не хватило — атрибут не проставлялся.
- **`sizes` в блоке преимуществ требовал `100vw` вплоть до 1280 px**, хотя картинка занимает треть строки: грузился кадр вчетверо шире нужного.
- **Не было favicon** — каждая загрузка страницы давала 404 в консоли. Иконка собрана из буквы «Б» в фирменных цветах, плюс `apple-touch-icon`.
- **Доступное имя логотипа не совпадало с видимым текстом** — нарушение «Label in Name» (WCAG 2.5.3): человек, управляющий голосом, говорит то, что видит.
- **Цвет `timber` использовался для текста** при контрасте 3,4:1. В токенах он помечен как «только графика» — заменён на акцентный `ember` (5,5:1).
- **Скрытый заголовок стоял внутри `<ul>`**, где допустимы только `<li>`.
- В `deviceSizes` добавлена ступень **720 px**: кадры из видео имеют ровно такую ширину, и без неё браузер просил 828, растягивая исходник.

Что осталось и не чинится на нашей стороне: `unused-javascript` и `legacy-javascript` (~35 КБ) — это рантайм Next.js, и `bf-cache` — прямое следствие `force-dynamic`, который нужен, чтобы правки из админки появлялись на сайте сразу.

## Если что-то не запускается

**`npm` или `node` не находятся.** Node установлен в `C:\Program Files\nodejs`. Если команда не находится, добавьте путь в PATH текущей сессии:

```powershell
$env:PATH = "C:\Program Files\nodejs;" + $env:PATH
```

**Порт 3000 занят.** Запустите на другом:

```bash
npx next dev -p 3001
```

**Ошибка Prisma о рассинхроне схемы.** Пересоздайте базу:

```bash
npx prisma db push
```

**Пропали фотографии на сайте.** Значит, `public/uploads` пуст или база не знает о файлах. Выполните по очереди `npm run media:import`, затем `npm run db:seed`.
