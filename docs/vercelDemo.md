# Read-only демо на Vercel

**Это временная настройка только для показа визуала заказчику.** Не основной
способ размещения сайта — тот описан в README (локальный запуск на SQLite).
Когда заказчик даст добро на реальный запуск, БД и хранилище файлов нужно
будет перенести на постоянные сервисы (Postgres/Neon/Turso + Vercel Blob или
аналог) — это отдельная задача, не то, что сделано здесь.

## Что изменилось ради этого

SQLite и папка с фото/видео по умолчанию не попадают в git — они локальные
и генерируются командами `media:import` / `reviews:import` (см. README).
На Vercel исходной папки с материалами нет, а файловая система в проде
доступна только на чтение. Поэтому для демо пришлось:

1. **Закоммитить `prisma/demo.db`** — снапшот базы с тем же контентом, что
   на локальном сайте (8 проектов, 10 объектов, 5 отзывов, тексты,
   настройки), но **без заявок и без данных аналитики**. Это не тот файл,
   с которым вы работаете локально (`prisma/dev.db` по-прежнему в
   `.gitignore` и не трогается).
2. **Закоммитить обработанные фото и видео** из `public/uploads/` —
   только webp/mp4-версии, которые реально показывает сайт. Оригиналы,
   файлы из админки и вложения заявок остаются вне git — см. правила
   в `.gitignore`.
3. **`next.config.mjs`**: добавлен `outputFileTracingIncludes`. Next.js
   сам определяет, какие файлы нужны каждой странице, но `demo.db`
   открывается по строке подключения (`DATABASE_URL`), а не через
   `import`/`require` — автоматический анализ такое не видит. Без этой
   строки Prisma на Vercel не найдёт базу вообще.
4. **`package.json`**: добавлен `postinstall: prisma generate` — Vercel
   должен собрать клиент Prisma под свою платформу (Linux) при каждой
   установке зависимостей.

Проверено локально: собранный `next build` с `DATABASE_URL` на `demo.db`
кладёт файл базы в трассировку всех маршрутов (`.next/server/**/*.nft.json`),
и `next start` с тем же окружением отдаёт 200 на всех страницах.

## Переменные окружения в Vercel

Проект → **Settings → Environment Variables**. Раньше их не было — при
первом деплое сайт работал только потому, что страницы не пытались всерьёз
читать базу (или падали тихо через `safeQuery`). Теперь нужно добавить:

| Переменная | Значение | Зачем |
|---|---|---|
| `DATABASE_URL` | `file:./demo.db` | Без этого Prisma возьмёт значение из закоммиченного `.env` (`file:./dev.db`) — а такого файла на Vercel нет, каждый запрос к базе будет падать |
| `AUTH_SECRET` | случайная строка от 32 символов | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `ADMIN_LOGIN` | что угодно | Пароль от админки на демо — не обязательно совпадает с локальным |
| `ADMIN_PASSWORD` | что угодно | — |
| `NEXT_PUBLIC_SITE_URL` | адрес вида `https://batyr-xxx.vercel.app` | Влияет только на sitemap и абсолютные ссылки Open Graph, на вёрстку не влияет |

`NEXT_PUBLIC_YANDEX_MAPS_API_KEY` и `NEXT_PUBLIC_YANDEX_METRIKA_ID` можно не
задавать — карта покажет статичный фолбэк со ссылкой, счётчик просто не
подключится.

## Build Command в Vercel

По умолчанию Vercel сам выполнит `next build`, а `postinstall` из
`package.json` должен успеть собрать клиент Prisma заранее. Если сборка
всё же упадёт с ошибкой вида «did you forget to run prisma generate»,
самый надёжный способ — переопределить команду сборки явно:

**Settings → Build & Development Settings → Build Command:**
```
prisma generate && next build
```

## Что будет работать, а что нет

**Работает как обычный сайт:** главная, каталог с фильтрами, карточки
проектов, галереи, лайтбокс, реализованные объекты, страница производства,
видеоотзывы, калькулятор (посчитает по заглушкам цен — это не про Vercel,
так же и локально, см. README), карта-фолбэк, все переходы.

**Не работает — и не должно:** база на Vercel открыта только на чтение.

- Формы (заявка, калькулятор, индивидуальный проект) примут данные на
  клиенте, но сохранить в базу не смогут — покажут собственное сообщение
  об ошибке («Не получилось отправить…»). Это существующая обработка
  ошибок в коде, не баг демо-режима.
- Вход в `/admin` сработает (это просто подписанная кука, БД не нужна),
  но любое сохранение — CRUD проекта, отзыва, настроек — вернёт ошибку
  по той же причине.
- Собственная аналитика (просмотры, события) тихо не запишется —
  в коде это тоже уже обрабатывается без падений.

Ничего из этого не крашит страницы: все обращения к базе в проекте
обёрнуты в `try/catch` или `safeQuery`, так что демо выглядит целиком
рабочим сайтом, просто без сохранения новых данных.

## Как обновить демо-снапшот

Если контент в локальной базе изменился и это нужно показать в демо:

```bash
# из корня проекта
cp prisma/dev.db prisma/demo.db
```

Затем вручную удалите из `demo.db` тестовые данные аналитики и реальные
заявки, если они там появились (в `/admin/leads` вручную, либо через
Prisma Studio: `npx prisma studio` с `DATABASE_URL=file:./prisma/demo.db`).
Закоммитьте — Vercel передеплоит сайт с новым снапшотом.
